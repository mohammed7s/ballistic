A puts the task first and feels closest to a useful Android prototype. B exposes the local runtime more directly. C moves input toward the thumb, but its softer typography feels less like a technical demo.

Reference notes & design decisions

Material’s bottom-sheet guidance informed C’s lower input placement. Nothing’s hardware-inspired interface informed B’s compact separation of status and task—not its dot typography. C explores a simple notebook hierarchy; it is an original composition rather than a reference copy.

All three use Ballistic’s existing logo, identical example content, and 44–48px minimum button heights in this web study. Native Android targets still need a 48dp minimum. A and B place the composer earlier in reading order; C favors reach. Keyboard behavior and secure approval must be validated in the native app.

Design study only. Task history and device readiness are sample states. No model is loaded, no task is executed, and no network request is made. Embedded llama integration and the Android app are unchanged.

Agent OS: a system-level AI assistant on a GrapheneOS fork

Mohammed Husari · Draft for discussion, please don't forward further without asking.

Why this project

A phone you talk to instead of tap: "reply to Ali that I'm late", "order my usual", "what did I miss on Signal?" It must drive any app, run its models locally or on hardware we own, and be safe against content that tries to hijack it. No ordinary app can do that; everyone who has shipped it owns the platform.

Google ships it: Gemini

Since Feb 2026 Gemini completes multi-step tasks inside Uber, DoorDash and Grubhub on the Galaxy S26 and Pixel 10. It works because Gemini is privileged system software. Selected apps, US/Korea, cloud model, no third-party access.

Hardware makers tried it: Doubao

Dec 2025: ZTE/Nubia shipped a phone with ByteDance's Doubao agent granted INJECT_EVENTS at OS level. It drove any app. Within days WeChat, Alipay and banks logged users out server-side. The tech works; the ecosystem decides who may use it.

Android gets native AI APIs, later

The EU DMA decision (16 July 2026) forces Google to give third-party assistants the 11 capabilities Gemini uses. Deadline Android 18 / Aug 2027, five behind certification, EU scope and AOSP availability unclear.

The privileges are the hard part, not the agent. Google grants them to itself, ZTE granted them to ByteDance, Android may grant them to certified apps in 2027. We grant them to ourselves now by forking GrapheneOS on Pixel: OS-maker position, inherited hardening, Pixel hardware. When Android's native APIs arrive, the same agent can ship as a certified app on stock Android.

What we add

  • AgentManagerService in system_server: the only gateway to screen capture, input injection, notifications, telephony, app data, model routing and per-app policy.
  • Trusted Confirmation dialog in SystemUI that ignores injected input, so the agent can never approve its own sends, payments or deletes.
  • Agent app (privileged, platform-signed, persistent): wake word, speech, planner, reader, skills library, model backends.
  • Agent IME: a system keyboard used to type into any field.
  • Model routing: on-device, home GPU over WireGuard, or opt-in cloud (off by default); per-app rules enforced by the OS; status-bar indicator.
  • SELinux domains, our signing keys, our OTA server; GrapheneOS hardening unchanged.

Design rule: the agent can touch anything on the phone except the confirmation dialog. Out of scope: spoofing attestation or Play Integrity; automating logins, payments or identity checks; hiding the agent from apps' fraud detection.

2. Input path (frameworks/native)

WhereWhat
Modservices/inputflinger/dispatcher/InputDispatcher.cppWhen the focused window carries the trusted-confirmation flag, drop every event whose InputEvent::isFromSource is an injected source (uid ≠ the physical device's) before dispatch. Real touchscreen events pass unchanged. This is the one rule the agent cannot get around.
Modservices/inputflinger/dispatcher/InputDispatcher.cppTag events injected by AgentManagerService with a distinct injector uid so apps that ask (MotionEvent.getDeviceId) see a normal device id, while the dispatcher itself can still tell them apart for the rule above.

WhereWhat

WhereWhat
Newpackages/apps/Agent/Privileged system app (/system_ext/priv-app, platform-signed, android:persistent="true"). 7. Keys, build and updates

WhereWhat
Cfgkeys/<device>/ (GrapheneOS script/generate-keys flow)Generate our own AVB, platform, releasekey, OTA and verity keys offline; sign on an isolated signer, never the build host.
CfgBootloaderFlash our AVB public key (fastboot flash avb_custom_key), relock. Phone boots "yellow" with our key, as GrapheneOS does with theirs.
CfgCIOn each GrapheneOS stable tag: rebase our patch series (one commit per row above), build, flash the CI Pixel, run the capability suite (~20 apps + injection tests), then publish the OTA. Target: shipped within 7 days of upstream.

What is deliberately not changed

  • keystore2, Titan M2 paths, biometrics, DRM. The agent can bring up a fingerprint prompt but never satisfy it. Signal's database key stays out of reach; Signal is driven via its screen.
  • Attestation. We do not imitate Google's or GrapheneOS's keys. Banks that whitelist GrapheneOS's key specifically will fail on our fork; everything else behaves as on GrapheneOS.
  • GrapheneOS hardening (MTE, exec restrictions, profiles, Storage/Contact Scopes, sandboxed Play). Inherited unchanged. The Agent app runs under those restrictions too; the native inference library must be tested against them.
